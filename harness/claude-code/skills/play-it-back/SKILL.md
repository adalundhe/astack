# Play it back

Restate what the person wants, in a few lines they can correct.

From their message, the files they pointed at and their earlier decisions:

1. **Goal:** what they want to be true when this is done, in their terms.
2. **Problem:** what's wrong or missing now, and who it hurts.
3. **Done when:** what users will see or be able to do. Never "the code is written".
4. **Left out:** what you won't touch, and nearby issues you'll only note.
5. **Assuming:** each assumption, as a statement they can strike.

One plain line each. When this starts work, proceed on your best reading; a correction steers from there.
