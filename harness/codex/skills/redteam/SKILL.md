# Redteam

Lead-only proactive attack, fix, and re-review loop for an existing codebase or subsystem. Unlike **bugbash** (which starts from a reported or unclear bug description and solves it), **redteam** starts with vectored **review** first—actively hunting for defects across risk-classified vectors, dispatching workers to fix what it proves, re-running vectored **review**, and repeating until the person's stopping conditions are met or vectored review finds no remaining issues. Pairs freely with **clamber** whenever performance is part of the stated goal.

- **Watch & swap (all rounds, per **lead**):** enforce `settings.json` clocks (`reviewer_minutes`, `worker_minutes`, `researcher_minutes`, `wind_down_minutes`, `check_in_minutes`) across every spawned reviewer, worker, and researcher. Stamp UTC `Started / Wind down at / End by` into briefs (pass `--settings`/`--timeout` to `astack-dispatch run`), log starts in `LANES.md`, check `astack-status` every `check_in_minutes`, remind at wind-down, and swap overdue runs with a fresh successor carrying harvested artifacts/branch SHA and reset timers.
- **Isolated workspaces & strict role split:** workers implement every fix and optimization in isolated **slates** in-memory VFS volumes (`https://github.com/hyper-light/slates`, preferred when available) or git worktrees. Reviewers stay strictly read-only—they attack, reproduce, and verify submitted changes in isolated **slates** volumes or read-only review worktrees, **never writing or applying fixes themselves**; they return proven findings, reproductions, and recommended fixes to workers via the lead.
- **Cross-harness delegation ("agents as tools" — never halt mid-wave):** delegate to external-harness reviewers, workers, and researchers via `astack-dispatch spawn` / `batch` / `status` / `wait` / `kill` (never raw shell `&` or `nohup`). Never stop a red-team round or yield to the user when one harness's agent finishes while cross-harness agents are still live—join every active run with `astack-dispatch wait --all --json`, harvest all findings, and keep driving the attack -> fix -> re-review loop.

1. **Scope the target, approved live-testing environments, vectors, and stopping conditions (**run-it-back**, **lookup**, **rtfm**):**
   - Restate the target codebase/subsystem, attack lenses (correctness, security/**least-privilege**, concurrency/state, resilience/**fail-safely**, deploy/IaC safety/**safe-to-deploy**/**safe-iac**, observability, coding rules, docs, and performance if in scope), and **exact stopping conditions** given by the person (e.g., zero blocking issues, zero issues of any severity, specific latency/throughput/memory target, or round/time budget). If no custom stopping condition is specified, stop when vectored **review** returns **no remaining proven issues** (or only genuine human product/risk decisions remain).
   - Run **lookup** (`~/.astack/*/lessons/*/LESSON.md`, including related repos on cross-repo targets) and **rtfm** (dispatching `astack-researcher` with **how-it-works** / **analyze-environment** when the codebase or toolchain is unfamiliar) so reviewers attack real architecture, invariants, and past traps instead of guessing—and record every **approved live-testing target** in `TOOLS.md` and reviewer briefs (local dev builds/containers/sandboxes, approved hosted dev/staging or ephemeral preview environments, or live harnesses; **never production, real customer data, or unapproved shared environments**).
2. **Round N — Attack first via live-adversarial vectored **review**:**
   - Cut the target into risk-classified vectors (adding a mandatory `seams` vector via **blast-radius** whenever sliced by module/subsystem) and dispatch blind read-only `astack-reviewer` subagents from `reviewer_pool` (**review**, **adversarial-review**, `astack-review-ledger`).
   - **Actively try to break, disrupt, and limit-test the live system (never stop at static reading):** instruct reviewer waves to run the real code in local dev builds/environments, approved hosted dev/staging environments, or other live-testing harnesses (**test-drive**, **full-spectrum-testing**, **net-trace**) and *intentionally* attack its limits—illustrative, never exhaustive: malformed/oversized/hostile inputs, fuzzing, concurrency/race/lock-contention storms, load/burst/backpressure overload, crash-kill/restart & duplicate replay (**safe-to-rerun**), injected downstream timeouts/partitions/faults (**fail-safely**), resource/queue/FD exhaustion, and real non-privileged auth/RBAC/boundary probing (**least-privilege**). Reviewers stay read-only on source code, clean up any temporary live test state/processes they create, and save standalone failing exploit/disruption/repro scripts (or exact conflicting citations for spec/doc/rule contradictions) outside `repo/`.
   - Verify every blocking finding on rerun, merge overlaps only by fix-equivalence, and check **no-leaked-secrets** and **technical-writing** drift.
   - **Evaluate stopping conditions after every review pass:**
     - **Done:** vectored **review** returns no remaining proven issues (or every user-specified stopping condition is met) -> proceed to Step 5.
     - **Human trade-off / pool exhaustion:** if a finding requires a product/functionality trade-off or `landing_blocked: true` remains after exhausting `reviewer_pool` and automated stress/formal passes (**full-spectrum-testing**, **formal-validate**), escalate plainly via **decisions-in-plain-words** without leaking internal ledger/pool bookkeeping.
     - **Stall / oscillation guard:** if consecutive rounds fail to reduce verified issues or re-introduce already-fixed defects, stop looping, log the dead ends (`decided:` in `LANES.md`), and escalate the underlying architectural tension with concrete options.
3. **Return issues & dispatch workers to fix (direct, **dagify**, or **treeify**):**
   - Return/log the round's verified issues clearly (plain user/system impact, runnable repro or contradiction citation, recommended fix—no internal ledger narration).
   - Scale remediation planning to the complexity of the findings:
     - **Focused / independent fixes:** dispatch `astack-worker` lane(s) directly (**fix-it**, **tests-assert-behaviour**) with non-overlapping writable paths, failing reproductions, and prior rejected theories / failed fix attempts (`decided:` via `astack-decisions`).
     - **Complex / interdependent fixes:** plan a reviewed dependency graph with **dagify** (or decompose bottom-up component waves with **treeify** when findings expose broken subsystem boundaries, or coordinate multi-repo fixes with **cross-repo**), then execute lanes via **lead** (`astack-verify-merge`, `astack-check-gates`).
4. **Pair freely with **clamber** when performance is part of the goal (then re-review):**
   - Follow **work -> robust -> fast**: land correctness, security, and reliability fixes from Step 3 first so performance runs on a tested baseline.
   - Whenever performance, latency, throughput, memory, or tail variance ($\sigma$) is part of the stated goal (or vectored review uncovers real performance defects), pair with **clamber** (backed by **benchmarking**, **baseline**, and **ab-test**): baseline median and $\sigma$, hill-climb in isolated worker commits, revert regressions, preserve all functionality (**never-trade-functionality**), and route kept optimizations back into the next vectored **review** pass.
   - **Loop back to Step 2:** resubmit the updated codebase (including all previously saved failing reproductions for **prove-it** verification and a `seams` check on changed interfaces) to a fresh vectored **review** round, repeating Steps 2–4 until the stopping conditions are met or vectored review returns no issues.
5. **Squish, clean up, run **lookback** + **make-it-stick**, and report:**
   - Run **squish** if multi-round fix/optimization commits or generated PRs can be cleanly rebased, squashed, or combined before final handoff/merge (preserving bisectable **clamber** commits when useful).
   - Sweep **no-leaked-secrets** and run **cleanup** to remove ephemeral Slates volumes/worktrees, debug captures, and scratch files.
   - Run **lookback** across all red-team rounds—proven defects, reproductions, rejected theories, failed attempts, remediation DAG/tree choices, and any **clamber** before/after measurements—to save, update, or prune `~/.astack/<project_name>/lessons/<lesson_name>/LESSON.md` lessons, paired with **make-it-stick** (dispatching a fresh worker + **review** for any structural code/type/lint/hook/test guard).
   - Report plainly (**wat**, losses first): rounds executed, stopping condition reached, every issue found and proven fixed (with runnable **prove-it** evidence and verified SHAs), any **clamber** median/$\sigma$ results, and any remaining accepted risks or human calls.
