# Run it back

Restate what the person asked for in short, easily corrected lines so misreads surface before work starts.

From their message, referenced files, and earlier decisions, state one plain line each for:

1. **Goal:** what should be true when this is done, in their terms.
2. **Problem:** what is broken or missing today and who it affects.
3. **Done when:** what users will see or be able to do (never just "code is written").
4. **Out of scope:** what you won't touch, plus adjacent issues you'll only note.
5. **Assumptions:** concrete statements the person can strike or correct.

If you're starting work, proceed on your best reading rather than blocking on confirmation; adjust if corrections arrive.
