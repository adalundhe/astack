# Play with me

Build a quick, throwaway demo so the person can try an idea before full implementation. Offer one proactively whenever showing beats describing.

1. **Pick the focus:** isolate the UX, API shape, or trade-off that's easier to try than explain.
2. **Build the smallest demo:** clickable mockup, short API script, CLI run, or sample data run.
3. **Stub the rest** and state explicitly what's mocked.
4. **Make it runnable in one command** locally or in an approved environment. Touch no real data and make no external calls so the person can experiment safely.
5. **Run it yourself first** to confirm it works cleanly.
6. **Share it concisely:** what it shows, the command to run it, and what to try.
7. **Keep moving on unblocked work** while waiting for reactions; let feedback guide the real implementation.
8. **Keep it out of production code**. Place throwaway files in scratch or cache outside the repo. Delete the prototype once the real version lands, or promote it cleanly to an example.

**Done when:** the demo runs in one command with no real side effects. Share the command and what to try.
