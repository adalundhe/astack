# Bugbash

Lead-scoped workflow for tackling a bug with a swarm of read-only reviewers before writing a line of fix code—converging on the verified root cause and minimal fix approach through peer **challenge**, then implementing with **fix-it** and verifying with full original context.

1. **Gather the full bug dossier (**rtfm**):** read the bug report and fetch every linked issue, PR, doc, commit, log, trace, or screenshot mentioned in it. Keep this dossier intact for **both** the investigation swarm and the post-fix reviewers.
2. **Dispatch a read-only reviewer swarm across multiple angles:** spawn blind `astack-reviewer` subagents (or `astack-dispatch run --role reviewer` across approved models in `reviewer_pool`, enforcing `reviewer_minutes` / `wind_down_minutes` / `check_in_minutes` from `settings.json`) assigned to complementary investigation vectors (e.g., failing path & callers, state/concurrency, input/protocol boundaries, recent regressions). Give every reviewer:
   - the full bug description and all fetched linked context;
   - explicit instructions to use **find-it** in order—confirm on a real scenario, collect runtime evidence, **shrink the repro first**, and then narrow and prove root causes—**without modifying the code under review** (any candidate fix or before/after check must be tested only in an isolated **Slates VFS volume** (preferred when available) or **throwaway scratch worktree** outside the repo under review);
   - instructions to propose one or more concrete, minimal fix approaches (noting trade-offs and **blast-radius**), validating proposed fixes in a Slates VFS volume (preferred when available) or throwaway scratch worktree where practical.
3. **Run peer **challenge** rounds with fresh runs, reset timers, and a convergence stop rule:**
   - **Dispatch fresh read-only runs per round:** reviewers that have finished—especially one-shot cross-harness runs via `astack-dispatch`—have already exited and cannot be messaged in place. For each challenge round, spawn fresh `astack-reviewer` runs (or `astack-dispatch run --role reviewer`), hand every reviewer the full set of peer reports (shrunk repros, runtime evidence, root-cause diagnoses, and proposed fix options), reset timers to a fresh `reviewer_minutes` window (`Started / Wind down at / End by` UTC timestamps, passing `--settings`/`--timeout` to `astack-dispatch run`, logged in `LANES.md`), and instruct them to use **challenge** to interrogate each other's reasoning and disprove weak hypotheses (testing competing proposed fixes only in isolated **Slates VFS volumes** (preferred when available) or **throwaway scratch worktrees**, never touching the repo under review).
   - **Stop on convergence or stalled evidence (**no-picked-constants**, **decisions-in-plain-words**):**
     - **Converged:** competing hypotheses are disproved or conceded with runnable proof, leaving one verified root cause and minimal fix approach. Log every **rejected root-cause theory and rejected candidate fix approach** (with its disproving evidence) as `decided:` entries in `LANES.md` (queryable via `astack-decisions`), then proceed to Step 4.
     - **No convergence / stalled:** if a challenge round produces **no new runnable evidence** (no new failing check, trace, bisect point, or disproved hypothesis), if the split reduces to a product/architectural trade-off local evidence cannot settle, or if approved models/budgets are exhausted, **stop looping immediately**—do not keep spinning challenge rounds. Escalate to the person in plain language laying out each surviving root-cause hypothesis (its evidence and what remains unproved), each candidate fix approach with trade-offs and **blast-radius**, and the lead's recommendation so the person chooses how to proceed before any worker touches code.
4. **Dispatch worker(s) with **fix-it** in isolated workspaces:** once reviewers converge, dispatch `astack-worker` (or `astack-dispatch run --role worker`) in an isolated **Slates VFS volume** (preferred when available) or **git worktree** (`git worktree add <program>/<worker> -b <prefix>/<lane>`) with the converged root cause, shrunk repro, chosen fix approach, **rejected theories (`decided:` entries)** so dead ends aren't repeated, and explicit instructions to follow **fix-it** (minimal root-cause fix, behavior-focused tests, before/after proof, reporting any **failed fix approaches or attempts** back to the lead; workers never spawn subagents).
5. **Run vectored **review** on the worker's fix with the original bug dossier, rejected theories, and **prove-it**:** when the worker finishes, log any failed/reverted fix approaches or attempts reported by the worker as `decided:` entries in `LANES.md`, then run vectored **review** (`astack-review-ledger` + `astack-check-gates`) on the fix:
   - Pass the **initial bug report, all fetched linked documentation/issues, the shrunk repro, AND the rejected theories (`decided:` entries) plus failed fix approaches/attempts** to the post-fix reviewers just as the first reviewer batch received the bug dossier (giving each reviewer an isolated **Slates VFS volume** (preferred when available) or review worktree and requiring any proposed follow-up fix to be tested only in a **Slates VFS volume** or **throwaway scratch worktree**, never editing the worker's workspace).
   - Explicitly instruct every post-fix reviewer to use **prove-it** (verify before and after on the real artifact, rank evidence on the trust ladder, and return concise runnable proof and evidence).
   - Route any proven edge cases or gaps back to the worker to strengthen existing tests first and fix cleanly.
   - **Summarize and attach proof to the PR:** include the post-fix reviewers' summarized **prove-it** verification and attached runnable proof/evidence (commands, outputs, traces, screenshots, or benchmarks as applicable) in any PR generated for the fix (**watch-pr**).
6. **Sweep and clean up:** verify **no-leaked-secrets** on the diff and PR evidence, and run post-review **cleanup** (removing temporary `<file>_DEBUG_<shorthash>.<type>` captures, throwaway scratch worktrees / ephemeral Slates VFS volumes, and temp artifacts while preserving the final PR verification evidence) before landing or opening the PR (**watch-pr**).
7. **Turn fixes, rejected theories, and failed attempts into durable lessons (**make-it-stick**):** once the fix clears post-fix review, the **lead** runs **make-it-stick** over the final fix, rejected root-cause theories (`decided:` entries), and failed fix approaches/attempts—recording scoped, evidence-backed lessons in `<repo>/LESSONS.md` (and `~/.config/astack/LESSONS.md` for workflow lessons) and applying the structural fix ladder (architecture -> types -> lint/hook -> test -> docs last) so the root bug class and dead-end traps don't recur.
